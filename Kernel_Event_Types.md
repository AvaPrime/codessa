# Kernel Event Types

## Overview
The Codessa Kernel uses an event-driven architecture to enable real-time communication between components. This document describes all events emitted by the kernel, their payloads, and typical use cases.

## Event Categories
- **System Events**: Core kernel lifecycle events
- **Agent Events**: Agent registration and management events
- **Directive Events**: Task execution and completion events
- **Memory Events**: Data storage and retrieval events
- **Planning Events**: Goal decomposition and task planning events
- **Cognitive Events**: Insights and learning events

## System Events

### system.ready
- **Description**: Emitted when the Codessa Kernel has been successfully initialized and is ready for operation.
- **Payload**: `{ timestamp: string, version: string, components: string[] }`
- **Use Case**: Trigger startup routines or notify connected components of operational readiness.
- **Example Handler**:
  ```typescript
  kernel.on('system.ready', (data) => {
    console.log(`Kernel v${data.version} ready at ${data.timestamp}`);
  });
  ```

### system.shutdown
- **Description**: Emitted during the shutdown sequence of the Codessa Kernel.
- **Payload**: `{ timestamp: string, reason: string }`
- **Use Case**: Perform cleanup operations or save state to prevent data loss.
- **Example Handler**:
  ```typescript
  kernel.on('system.shutdown', (data) => {
    console.log(`Kernel shutting down: ${data.reason}`);
    // Perform cleanup
  });
  ```

## Agent Events

### agent.registered
- **Description**: Emitted when a new agent is registered successfully.
- **Use Case**: Update UI components or log changes to registry.

### agent.modelPreferenceChanged
- **Description**: Emitted when an agent's preferred model has been changed.
- **Use Case**: Adjust routing logic or notify relevant operators.


## Directive Events

### directive.started
- **Description**: Emitted when a directive starts execution.
- **Use Case**: Provide real-time feedback or log execution attempts.

### directive.completed
- **Description**: Emitted upon successful completion of a directive.
- **Use Case**: Analyze results, free up resources, or log success details.

### directive.failed
- **Description**: Emitted if a directive fails to execute successfully.
- **Use Case**: Initiate error recovery, log failure reasons, or alert administrators.

## Memory Events

### memory.queried
- **Description**: Emitted after a successful query to the memory system.
- **Use Case**: Analyze queries or cache frequent searches.

### memory.stored
- **Description**: Emitted when data is stored successfully in memory.
- **Use Case**: Validate storage actions or replicate changes across systems.


## Planning Events

### goal.created
- **Description**: Emitted when a new goal is created and a task plan is generated.
- **Use Case**: Track goal creation activities or update task boards.

### plan.created
- **Description**: Emitted when a task plan is created for a goal.
- **Use Case**: Validate plan integrity, initiate execution, or render visual task representations.

### plan.completed
- **Description**: Emitted upon successful execution of a plan.
- **Use Case**: Analyze plan outcomes or prepare subsequent phases.

### plan.cancelled
- **Description**: Emitted when a plan is cancelled before completion.
- **Use Case**: Adjust schedules, notify stakeholders, or release resources.

## Cognitive Events

### cognitive.insight
- **Description**: Emitted when new insights are generated by the cognition loop.
- **Use Case**: Utilize insights for continuous learning or reporting.
